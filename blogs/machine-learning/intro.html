Part 1: The Earth is Not IID (Introduction & Terminology)

November 2026  |  Earth System ML

Building a machine learning model that performs well on a training set is easy. Building one that generalizes to unseen real-world data requires strict adherence to methodological best practices. This is particularly true in Earth System Sciences where datasets involve complex spatiotemporal dependencies.

Standard data science tutorials often rely on datasets where predicting house prices or classifying images works seamlessly with random data splits. In operational meteorology and climate downscaling, using these naive approaches guarantees failure. The fundamental rule of this blog series is simple: The Earth is not IID (Independent and Identically Distributed).

This series will guide researchers and meteorologists in implementing rigorous and physically consistent machine learning pipelines using modern stacks like PyTorch, JAX, Xarray, Scikit-learn, LightGBM, and Optuna. Before we dive into the code in subsequent posts, we must first establish the core terminology and philosophy that will dictate our architecture.

Core Terminology and The Myth of IID

  • IID (Independent and Identically Distributed): The assumption that each data point is completely independent of the next. In atmospheric data, adjacent grid cells in space and consecutive time steps in time are highly correlated. Treating them as IID is mathematically flawed.
  • Autocorrelation: The degree of similarity between a given time series and a lagged version of itself over successive time intervals. Because weather patterns persist, yesterday's 500 hPa geopotential height heavily influences today's values.
  • Data Leakage: A fatal flaw where information from outside the training dataset is accidentally used to create the model. In Earth sciences, this often happens through preprocessing leakage (fitting a scaler on the entire 1980 to 2020 dataset before predicting 2020) or detrending leakage (removing a global warming trend calculated using the test data).
  • Ablation Study: Systematically removing components of a machine learning framework to quantify its individual contribution. We use this to defend against unnecessary complexity.

Our Guiding Philosophies

To build operational-grade models for tasks like S2S bias correction or predicting SST anomalies, we will strictly adhere to the following principles throughout this series:

  1. Physics First, Algorithms Second: We do not dump hundreds of raw variables into an XGBoost model and hope it finds a pattern. For feature selection, we always start with domain-driven selection before running algorithmic feature importance. We must choose variables with established dynamical relationships like specific teleconnection indices or moisture transport corridors.
  2. Interrogate the Data: Before deciding on a neural network architecture, you must interrogate your data. You must determine the spatial resolution, the temporal frequency, and the seasonality. The architecture must serve the physical reality of the data.
  3. Explainable AI is Mandatory: Model transparency is a requirement rather than a bonus. We will utilize Layer-wise Relevance Propagation and SHAP to ensure our models are learning true physical mechanisms instead of spatial noise.
