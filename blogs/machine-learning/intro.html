Part 1: The Earth is Not IID (Introduction & Terminology)

November 2026  |  Earth System ML

Building a machine learning model that performs well on a training set is easy. Building one that generalizes to unseen, real-world data—especially in Earth System Sciences involving complex spatiotemporal dependencies—requires strict adherence to methodological best practices.

Standard data science tutorials often rely on datasets where predicting house prices or classifying images works seamlessly with random data splits. In operational meteorology and climate downscaling, using these naive approaches guarantees failure. The fundamental rule of this blog series is simple: The Earth is not IID (Independent and Identically Distributed).

This series, Building Robust ML Frameworks for Earth Sciences, will guide researchers and meteorologists in implementing rigorous, physically consistent machine learning pipelines using modern stacks like PyTorch, JAX, Xarray, Scikit-learn, LightGBM, and Optuna. Before we dive into the code in subsequent posts, we must first establish the core terminology and philosophy that will dictate our architecture.

Core Terminology & The Myth of IID

  • IID (Independent and Identically Distributed): The assumption that each data point is completely independent of the next. In atmospheric data, adjacent grid cells (space) and consecutive time steps (time) are highly correlated. Treating them as IID is mathematically flawed.
  • Autocorrelation: The degree of similarity between a given time series and a lagged version of itself over successive time intervals. Because weather patterns persist, yesterday's 500 hPa geopotential height heavily influences today's.
  • Data Leakage: A fatal flaw where information from outside the training dataset (usually the future) is accidentally used to create the model. In Earth sciences, this often happens through preprocessing leakage (e.g., fitting a scaler on the entire 1980-2020 dataset before predicting 2020) or detrending leakage (removing a global warming trend calculated using the test data).
  • Ablation Study: Systematically removing components of a machine learning framework (a feature, a neural network layer, or a custom loss function) to quantify its individual contribution. We use this to defend against "complexity for complexity's sake."

Our Guiding Philosophies

To build operational-grade models for tasks like S2S bias correction or predicting SST anomalies, we will strictly adhere to the following principles throughout this series:

  1. Physics First, Algorithms Second: We do not dump hundreds of raw variables into an XGBoost model and hope it finds a pattern. For feature selection, we always start with domain-driven selection—choosing variables with established dynamical relationships (like specific teleconnection indices or moisture transport corridors)—before running algorithmic feature importance.
  2. Interrogate the Data: Before deciding on a U-Net, Graph Neural Network, or LightGBM, you must interrogate your data. What is the spatial resolution? Temporal frequency? Seasonality? The architecture must serve the data's physical reality, not the other way around.
  3. Explainable AI (XAI) is Mandatory: Model transparency is a requirement, not a bonus. We will utilize Layer-wise Relevance Propagation (LRP), Integrated Gradients, and SHAP to ensure our models are learning true physical mechanisms rather than spatial noise.
